CASE STUDY 02 · AI 知识生产力

NotAgent

AI Knowledge Agent

把分散在 AI 对话中的有效结论，转化为可收藏、可编辑、可分类并能再次利用的个人知识资产。

PROBLEM / 问题定义

AI 对话很多，能复用的知识很少。

高频使用 AI 进行研发学习和问题排查时，有价值的过程、草稿与结论往往仍以会话为单位分散保存。用户需要在长回答中局部筛选内容，持续编辑，并按自己的结构整理，而不是再次进行一次对话。

NotAgent 将目标用户收敛为高频使用 AI 的知识工作者，并把产品价值定义为：降低从“得到回答”到“形成可复用知识”的整理成本。

SOLUTION / 核心闭环

让每次对话进入知识工作流。

功能不是独立堆叠，而是围绕内容如何被捕获、整理和再次使用形成连续路径。

01

AI 对话

通过多模型服务完成研发学习、问题排查和方案讨论。

02

内容收藏

选择回答中的局部文本，而不是保存整段长会话。

03

知识编辑

继续修改、补充和组织已收藏内容。

04

分类整理

使用分类、标签和文件夹建立个人结构。

05

AI 建议

由模型辅助整理，但修改前保持用户确认。

06

再次利用

通过搜索、浏览和再次打开回到已有知识。

PRODUCT DECISIONS / 产品决策

先验证知识闭环，再扩大 AI 能力。

产品路线围绕真实用户价值和交付风险收敛，而不是以 RAG、Agent 或 MCP 的数量衡量完成度。

01

从通用 Chat 收敛为 Knowledge Agent

假设

用户需要的不是更多对话，而是把高价值内容保存、整理并再次利用。

证据

内部 Alpha 暴露的主要问题集中在回答收藏、知识编辑、列表浏览和再次打开，而不是更复杂的生成能力。

决策

暂停尚未验证的 RAG、Agent 与 MCP，先完成“对话—收藏—整理—复用”的核心闭环。

02

用阶段门控制产品范围

假设

桌面 AI 产品需要先证明核心路径可用，再扩大模型与自动化能力。

证据

将路线拆为 MVP、体验收敛、Windows 桌面化、Internal Alpha、Demo Readiness 和 Closed Beta。

决策

为每个阶段明确功能范围、非目标、验收标准和 Go / No-Go 门槛。

03

模型能力不与页面耦合

假设

用户会使用不同模型服务，产品需要稳定的调用边界和可理解的响应模式。

证据

统一 Provider 支持 Demo、通义、豆包、DeepSeek 与自定义 OpenAI-compatible 服务。

决策

建立独立 Provider 服务层，并规划快速回答、深度思考和跟随模型三种产品模式。

04

把隐私规则做进产品方案

假设

BYOK 桌面应用的可信度取决于密钥、正文和卸载行为是否可解释。

证据

API Key 使用 Windows DPAPI 加密；Renderer 仅读取 hasApiKey；连接测试不发送聊天或知识正文。

决策

明确密钥不可回显、普通卸载保留知识、数据迁移可回退，以及 AI 修改前用户确认。

PRODUCT / 产品界面

围绕同一闭环组织界面。

Chat 负责产生内容，Knowledge 负责沉淀内容，Provider 负责管理模型能力与安全边界。

INTERNAL ALPHA / 用户验证

观察真实使用，再决定迭代优先级。

用户反馈按缺陷、体验优化、产品候选和无法复现分类，并结合核心价值、Demo 风险与实现成本排序。

DELIVERY / 安全与交付

AI 能力之外，产品还要可信地运行。

BYOK 与隐私

Windows DPAPI 加密 API Key；Renderer 只读取配置状态；连接测试不发送聊天或知识正文。

可理解的错误

区分鉴权、配置、超时、网络与限流问题，让用户知道下一步该做什么。

Windows 生命周期

Electron 托管 FastAPI 子进程，包含健康检查、崩溃恢复、退出清理和 NSIS 安装器。
